# 怎么发一个更新（让所有装了 App 的人都收到「有新版本」）

App 里的「检查更新」去看的是
**https://github.com/MartinMax0711/VoiceCollector-/releases/latest**。
仓库是公开的，谁装了这个 App 谁都能收到提示，不需要登录。

## 两种更新

| | 网页层更新（绝大多数情况） | 完整安装包 |
|---|---|---|
| 改了什么 | `web/` 下的 js / css / html | Electron 本体、`desktop/main.js`、内置模型 |
| 大小 | 约 400 KB | 约 614 MB |
| 用户怎么装 | App 里点「更新」→「重启生效」，几秒钟 | 下载 dmg 重新拖进「应用程序」 |
| 要签名吗 | 不要 | 不要（但首次打开要右键→打开） |

为什么网页层更新不用 Apple 签名：它不碰 App 本体，只是解压到
`~/Library/Application Support/VoiceCollector/web-update/<版本>/`，
由本地服务器优先读取（`desktop/lib/server.js` 的 overlay）。

## 发网页层更新

1. 改 `web/version.json` 里的 `version`（必须比上一个大，比如 1.0.1 → 1.0.2），`notes` 写这次改了什么
2. 先跑演练，全过才发：
   ```
   cd desktop
   npm run preflight
   node scripts/rehearse.mjs --rounds 3
   ```
3. 打更新包：
   ```
   node scripts/build-web-update.mjs
   ```
   最后一行会打出 `sha256`
4. 在 GitHub 上 **Releases → Draft a new release**
   - Tag：`v1.0.2`
   - 附件：`desktop/dist/release/web-1.0.2.zip`（**文件名必须是 `web-<版本>.zip`**）
   - 正文照这个格式（每行一条会显示在 App 的更新弹窗里）：
     ```
     - 修好了 xxx
     - 新增 yyy
     sha256: <第 3 步打出来的那一串>
     ```
   - 如果这次还要求新的程序本体，加一行 `minShell: 1.0.2`（外壳版本低于这个的用户会被引导去下完整包）
5. **Publish release**（不要勾 pre-release；草稿不会被检测到）

## 安全网

- **坏更新会自己退回**：新版本启动时先写一个 `.pending` 标记，界面 `init()` 成功才删掉。
  如果新版本一打开就崩，下一次启动看到标记还在，会自动丢掉这个版本、回到 App 自带的版本。
  （`node scripts/rehearse.mjs --only badupdate` 专门测这个）
- 设置页「关于」里有「退回上一版」手动出口。
- 校验：下载后对比 `sha256`，对不上就不装。
- 录课的时候绝不会更新，也不会弹窗；只在顶栏亮一个小按钮。
