# 本地小 AI 说明（web/js/llm.js）

> 一句话：**它是给笔记"润色"的，不是给你"读懂这节课"的。**
> 它在你的电脑里跑，不联网，不需要 API Key，也不要钱。代价是它比 Claude 笨很多，
> 而且有时候会说错——所以这个应用把它关在一个很小的笼子里用。

---

## 一、它解决的是什么问题

打开这个应用录一节课，会经过三步：

1. **Whisper**（`web/js/whisper.js`）把英文课堂录音转成英文文字。
2. **离线结构化分析**（`web/js/localnlp.js`）用规则从转写稿里**抽**出：
   主题段落、定义句、考点句、作业与 deadline、分点枚举、公式、术语表、课堂问答、疑似听错的地方。
3. **本地小 AI**（`web/js/llm.js`，就是本文说的东西）把第 2 步抽出来的东西，**用中文写成人话**。

第 2 步的问题在于：它准，但生硬。你拿到的是一堆英文句子的摘录，还是要自己翻译、自己组织。
第 3 步补的就是这个洞：把已经抽好的定义、考点、枚举、术语，改写成通顺的中文。

**注意这里的因果顺序**：小 AI 不是从三千句转写稿里"读懂"这节课再写总结——
0.5B～1.5B 的模型做不到这件事，硬让它做它就会编。
它每次只拿到一小撮**已经被验证过是老师原话**的素材，只做一件小事（"把这 4 条定义解释清楚"），
然后输出会被一道检查关卡拦一遍。素材是真的，任务是小的，所以它编不出太离谱的东西。

---

## 二、它能做什么

| 能做 | 为什么敢让它做 |
|---|---|
| 写一句话总结 | 素材是主题标题 + 高频术语 + 几句关键原话，它只是把它们串成中文 |
| 给每个主题段写一句中文说明 | 素材是这一段的 3 句关键句 |
| 把定义用中文解释清楚 | 素材是老师自己说的定义原话，一次只给 4 条 |
| 把零散的考点组织成中文清单 | 素材是"老师专门强调过"的那些句子 |
| 把 First / Second / Third 整理成中文步骤 | 素材是枚举原句，顺序也是原顺序 |
| 给术语表配中文释义 | 一次 8 个词，每个词附带它出现过的那句原话 |
| 回答"作业什么时候交""这节课重点是什么" | 先从转写稿里检索相关片段，再让它只根据片段回答 |

## 三、它**不做**什么（这些地方永远是原话 + 时间戳）

| 不做 | 原因 |
|---|---|
| **公式 / 例题 / 推导** | 小模型改公式几乎必错：会把 `1/2` 写成 `2`、把 `squared` 弄丢 |
| **作业的日期** | 它真的会把 "next Friday" 写成"下周三"。这是最不能错的地方，直接抄原话 |
| **课堂问答的原话** | 问答本来就是原话最有价值 |
| **可能听错的地方** | 这是让你回听用的，改写只会掩盖问题 |
| **你在课上打的标记** | 那是你自己写的，不该被它动 |

所以生成的笔记里，凡是涉及**日期、数字、公式**的，看到的都是转写稿原文。
中文叙述的部分旁边永远保留着"原话 + `[mm:ss]` 时间戳"，方便你回去核对。

## 四、三档模型、体积、下载时间

三个仓库都在 Hugging Face 上核实过真实存在，体积是**实际会被下载的那一个 `.onnx` 文件**的大小
（不是仓库总大小——仓库里各种精度加起来要大好几倍）。另外每个模型还要下 8～12MB 的分词器文件。

> 单位说明：下表一律是 **MiB**（字节数 ÷ 1048576）。Hugging Face 网页上显示的是十进制 MB/GB，
> 会比这里大 4～7%——比如"最好"档的 1165 MiB，HF 网页写的是 1.22 GB，是同一个文件。

| 档位 | 仓库 | WebGPU（q4f16） | 无 fp16 的 WebGPU（q4） | 纯 CPU（q8） | 建议内存 |
|---|---|---|---|---|---|
| 轻量 | `onnx-community/Qwen2.5-0.5B-Instruct` | **461 MiB** | 750 MiB | 488 MiB | 8 GB |
| 推荐 | `onnx-community/Qwen3-0.6B-ONNX` | **543 MiB** | 877 MiB | 589 MiB | 8 GB |
| 最好 | `onnx-community/Qwen2.5-1.5B-Instruct` | **1165 MiB** | 1705 MiB | 1506 MiB | 16 GB |

精确字节数（HF tree API 的 `size` 字段，2026-09 核对）：
`Qwen2.5-0.5B` q4f16 483,003,582 / q4 786,156,820 / q8 512,096,557；
`Qwen3-0.6B` q4f16 569,789,750 / q4 919,096,585 / q8 617,687,575；
`Qwen2.5-1.5B` q4f16 1,221,878,940 / q4 1,787,566,590 / q8 1,578,954,293。
三个 q4f16 都是**单文件**，没有配套的 `.onnx_data`。

**第一次要下多久**（只下一次，之后存在浏览器的 Cache Storage 里，完全离线）：

| 网速 | 461 MiB | 543 MiB | 1165 MiB |
|---|---|---|---|
| 校园 WiFi 好的时候（约 20 MB/s） | 约 25 秒 | 约 30 秒 | 约 1 分钟 |
| 一般宿舍 WiFi（约 5 MB/s） | 约 1.5 分钟 | 约 2 分钟 | 约 4 分钟 |
| 手机热点 / 网不好（约 1 MB/s） | 约 8 分钟 | 约 9 分钟 | 约 20 分钟 |

**务必在进教室之前、连着好网的时候先下好。** 下完之后用不用得上网都无所谓了。

如果你把模型文件手动放进 `web/models/<仓库名>/`（目录结构和 Hugging Face 上一样），
应用会优先读本地目录，连第一次下载都省了。没有就自动回退到网上下。

## 五、什么机器跑得动

应用会自己探测，你不用管。下面是它的判断逻辑，供你对照：

- **M 系列芯片的 Mac（M1/M2/M3/M4）+ Chrome/Edge**：WebGPU + fp16 都有，最理想。
  16GB 内存的推荐 1.5B，8GB 的推荐 0.6B。整理一节 90 分钟的课大约 **1～3 分钟**。
- **带独显的 Windows 笔记本（NVIDIA / AMD）**：同上。
- **Safari**：能跑，但 Safari 不给网页报告内存大小，应用会保守地只推荐 0.6B。
- **Intel Mac / 核显笔记本 / 没有 WebGPU**：退回 CPU 跑。**能出结果，但很慢**——
  一节课可能要 10 分钟以上，而且风扇会转、电池掉得快。建议插着电源用。
- **内存小于 8GB 或核心数少于 4**：应用会直接劝你别开，继续用抽取式笔记。

**省电方面做的事**：默认限制每次生成的长度（不让它写小作文）、wasm 线程数砍到一半核心、
优先走 GPU（GPU 定点运算比 CPU 满载省电）、笔记生成完主动释放显存。

## 六、跑飞了怎么办（这是最重要的一节）

小模型有几种典型的发疯方式，每一种都有专门的拦截：

| 发疯形态 | 怎么拦 |
|---|---|
| 输出空的 | 长度检查 |
| 同一句话重复 200 遍 | 行级 / 句级 / 6 字窗口三层重复检测 |
| 整段英文（只是把素材复读一遍） | 中文字符占比检查 |
| 乱码、控制字符、同一个字连打几十个 | 字符集检查 |
| 该写一句话结果写了 2000 字 | 长度上限 |
| 把提示词模板原样吐出来 | 模板泄漏检测 |
| **编数字、编日期** | 输出里 2 位以上的数字必须在素材里出现过，否则整段作废（"October"→"10 月"这种正常换算除外） |
| **编星期、编相对时间** | "下周三交"这种一个数字都没有的编造：中文的星期／明天／后天／下周／月底，素材里必须有对应说法（`Wednesday`、`tomorrow`、`next…`），否则整段作废 |
| **编中文数字日期** | "十一月十四日"换算成数字后同样要能在素材里找到 |
| **凭空冒出英文词** | 输出里 4 个字母以上的英文词必须在素材里出现过（允许单复数变形），拦"Gaussian process""Chapter Nine"这类编造的术语和人名 |
| **吐 HTML / Markdown 标题** | 输出先过一遍结构清洗（去掉 `<details>`、`<script>`、`# 标题`、分隔线、代码围栏），防止把笔记结构掀翻 |
| 生成超时 / 卡住 | 单次生成 60 秒软超时（到点让它自己收尾），再等 20 秒还不回来就硬放弃 |

**任何一条没通过，这一小节就原样退回抽取式输出**（也就是"原来那份笔记里的样子"）。
不是整篇作废，只是那一节。最坏情况下所有小节都失败，你拿到的就等于原来的抽取式笔记——
不会更差，更不会拿到一份胡说八道的笔记。

笔记的最后会如实写明：**这次请求模型 N 次，M 次采用、K 次因输出不可信被丢弃。**
如果你看到丢弃的次数很多，说明这台机器上这个模型状态不好，换个小一点的档位试试。

## 七、和"配 API Key 用 Claude"比，差在哪（老实说）

这一节不粉饰。

| | 本地小 AI（0.5B～1.5B） | 云端大模型（Claude 等） |
|---|---|---|
| 要不要 API Key / 花钱 | **不要，永远免费** | 要，按用量付费 |
| 要不要联网 | 第一次下模型要，之后不要 | 每次都要 |
| 录音上不上传 | **不上传，一个字节都不出你的电脑** | 转写稿要发到服务商 |
| 理解一整节课的能力 | **差**。它看不了全局，只能在小块素材上改写 | 好。能通读全程，真正做到"抓主线" |
| 中文表达 | 通顺，但偏套话，偶尔生硬 | 自然、准确 |
| 专业概念的解释深度 | 表面。常常只是把原话换个说法 | 能真正讲清楚，还能补背景 |
| **会不会说错** | **会**。见下面的具体例子 | 少很多，但也不是零 |
| 速度 | M 芯片上 1～3 分钟；CPU 上 10 分钟起 | 几十秒 |
| 笔记整体质量 | 比纯抽取式好一截，但离"能直接拿去复习"还有距离 | 基本能直接用 |

**两个真实的出错例子**（都是用 Qwen2.5-0.5B 实测跑出来的）：

- 术语表里，它把 `martingale`（鞅）的中文解释写成了**"马尔可夫过程"**。这是两个不同的东西。
- 问答里问"作业什么时候交"，老师原话是 `next Friday at 5pm`（下周五），它答成了**"周五晚上 5 点"**，
  把"下"字丢了。

第一种错误（把"鞅"解释成"马尔可夫过程"）**拦不住**——整句都是中文，没有编数字、
没有编星期、没有冒出素材以外的英文词，格式上看不出任何毛病。
**这是本模块能力的真实边界：它能拦住"格式上发疯"和"凭空冒出具体事实"，
拦不住"用素材里的词一本正经地说错关系"。**
同类例子：模型可能写出"这个定理最早由高斯提出"这种整句中文的编造，检查关卡放行。
所以每条中文旁边**永远保留老师原话和 `[mm:ss]` 时间戳**，复习时以原话为准。

第二种错误（`next Friday` → "周五"）现在**拦得住了**：时间说法接地检查会要求
输出里的"周五""下周"在素材里有对应的 `Friday` / `next`，对不上就整段退回抽取式。
（另外笔记里的作业日期本来就永远直接抄转写稿，不经过模型；见第三节。）

**好消息是回退机制确实在工作**：同一次实测里问"这节课的重点是什么"，
模型吐了一段几乎全是英文的东西，被中文比例检查拦下，应用直接改成把转写稿里
5 条最相关的原话摆出来，并注明"本地 AI 这次没给出可信的回答"。

所以：

> **本地小 AI 写的中文，要当成"一个学长帮你随手整理的笔记"来看，不是权威答案。**
> 笔记里每一条中文旁边都留着老师原话和时间戳，**凡是要拿去考试的内容，请对着原话再看一眼。**

如果你哪天愿意配一个 API Key，应用里的云端模式会明显更好。
但这整个模块存在的意义就是：**在你不想配 Key 的前提下，把离线这条路做到尽可能好。**

## 八、常见问题

**Q：模型下到哪了？会不会占满硬盘？**
A：存在浏览器的 Cache Storage 里（桌面版在 Electron 的用户数据目录）。占用就是上面表格里的体积，
一个模型 0.5～1.2GB。换模型会各存一份，不想要了可以在应用设置里清缓存。

**Q：可以只对某一节用小 AI 吗？**
A：可以。CPU 机器建议这么用——只润色"核心概念与定义"这一节，比整篇跑快得多。

**Q：它会不会把我的录音传出去？**
A：不会。模型权重从 Hugging Face 下载是**单向**的（只下不上），下完之后整个流程不发任何网络请求。
你可以下完模型直接断网验证。

**Q：为什么推荐 Qwen 而不是别的？**
A：这三个都是中文友好的小模型，且在 `onnx-community` 下有现成的 ONNX + q4f16 量化，
能被 transformers.js 的 `text-generation` 直接加载，不需要自己转换。
同体积下英文模型（Llama / SmolLM 一类）写中文明显更差。

**Q：Qwen3 不是会先"思考"一大段吗？**
A：是。`web/js/llm.js` 已经把它关掉了（`enable_thinking=false`），
另外还有一层兜底会把残留的 `<think>` 块剥掉。

## 九、给改代码的人

对外接口（`web/js/llm.js`）：

- `LLM_MODELS` —— 三档模型清单，含真实体积
- `llmAvailable()` —— 探测这台机器能不能跑，返回 `{ok, reason, device}`
- `recommendModel()` —— 按硬件推荐一个 id
- `new LocalLLM({model, onProgress, onStatus})` —— `load()` / `generate()` / `close()`
- `polishNotes(analysis, {ctx, llm, onStep})` —— 核心，输入 `localnlp.analyze()` 的结果，输出 Markdown
- `answerQuestion({question, analysis, session, llm})` —— 基于本节课的问答
- `checkOutput(text, {material})` —— 那道检查关卡，单独导出方便测试
- `GROUND_RULES` —— 每次调用都会带上的"铁律" system prompt

几个必须知道的坑，代码里都有详细注释：

1. `env.localModelPath` **必须是路径、不能是完整 URL**。transformers 4.3.0 的文件存在性探测
   判的是 `localPath` 是不是合法 URL，写成 `https://…/models/` 会让整个本地分支被跳过，
   于是明明本地有模型也会去网上重下 1GB。
2. `env` **不是**和 whisper.js 共享的：llm.js import 的是 `transformers.web.min.js`，
   whisper.js import 的是 `transformers.min.js`，两个不同的打包产物 → 两个模块实例 →
   **各自一份 `env`**，互不干扰（代价是页面上会有两份库，约 1MB JS）。
   即便如此，`allowLocalModels` / `localModelPath` 仍然是每次 `load()` 前按需设置的，
   因为同一个 `LocalLLM` 实例可能先后加载不同的模型，本地有没有那份权重是按模型变的。
3. Qwen3 的 `enable_thinking` 是通过 `tokenizer_encode_kwargs` 传进 chat template 的
   （transformers 会把它原样展开进 `apply_chat_template` 的参数）。
4. 生成超时用的是自定义 `StoppingCriteria` 子类（继承基类，`_call(input_ids)` 返回
   `boolean[]`，长度等于 batch size），通过 `generate` 的 `stopping_criteria` 传进去。
   web 打包产物里 `StoppingCriteria` / `StoppingCriteriaList` / `InterruptableStoppingCriteria`
   都是导出的；这里用自定义子类是因为要按"到点"而不是"外部打断"来停。
